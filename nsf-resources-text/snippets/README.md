# snippets/ — Context7-style tokenized corpus

Auto-generated by [`../scripts/tokenize_corpus.py`](../scripts/tokenize_corpus.py).
Each snippet is a self-contained section/sub-section of one of the source
documents in `nsf-resources/`, chunked to ≤ ~1,200 tokens, tagged with the
detected requirement strength, and pinned to a specific page span and
canonical source URL.

Inspired by [Context7](https://context7.com), [llms.txt](https://llmstxt.org),
and the broader *docs-as-tools-for-LLMs* movement — but applied to non-code
(regulatory / policy / grant-prep) corpora.

## Files

| File | Purpose |
| --- | --- |
| `snippets.jsonl` | One JSON record per snippet (canonical) |
| `snippets.contextual.jsonl` | Same records with an Anthropic-style `context_prefix` prepended (built by `scripts/contextualize.py`; opt-in via `retrieve.py --contextual`) |
| `snippets.context7.md` | Same records rendered as Context7 `TITLE / DESCRIPTION / SOURCE / TEXT` blocks |
| `parent_children.json` | Map `parent_id → [child_id, ...]` used by `retrieve.py --expand-parent` to merge sibling-part chunks into one hit |
| `index.md` | One-row-per-snippet table (id · strength · tokens · pages · title) |
| `summary.json` | Aggregate counts (snippets per doc, by requirement strength) |
| `by-doc/<doc>.jsonl` | Per-document JSONL shards so an LLM can load only what it needs |

## Snippet schema

```json
{
  "id": "pappg-24-1#II.D.2.b",
  "doc_id": "pappg-24-1",
  "doc_title": "PAPPG 24-1 (NSF 24-1)",
  "section_path": "II.D.2.b",
  "section_breadcrumbs": [
    "Chapter II",
    "D. Proposal Contents",
    "2. Sections of the Proposal",
    "b. Project Summary"
  ],
  "title": "b. Project Summary",
  "text": "Each proposal must contain a summary of the proposed project not more than one page in length. ...",
  "pages": [49],
  "source_pdf": "nsf-resources/pappg-24-1.pdf",
  "source_url": "https://www.nsf.gov/pubs/policydocs/pappg24_1/pappg_full.pdf",
  "requirement_strength": "required",
  "requirement_phrases": ["must", "should"],
  "char_count": 985,
  "est_tokens": 246,
  "source_label": "[NSF PAPPG 24-1 §II.D.2.b, p.49]",
  "version": "NSF 24-1",
  "effective_date": "2024-05-20",
  "chunk_hash": "sha256:d431b2729c31aab6",
  "cross_references": [
    {"raw": "Chapter II.E.1", "id": "pappg-24-1#II.E.1"},
    {"raw": "Section III.A",  "id": ""}
  ],
  "part": 1,
  "part_count": 1,
  "tags": []
}
```

### Field semantics

* **`id`** — stable, citable. PAPPG snippets use the actual outline path
  (`II.D.2.b`); other docs use a slug-of-heading path. Multi-part chunks get a
  `~p<n>` suffix.
* **`section_path`** — the doc-relative path component (`II.D.2.b`).
* **`section_breadcrumbs`** — full ancestry from the chapter title down,
  intended to be displayed verbatim by the LLM in citations.
* **`requirement_strength`** — one of `prohibited`, `required`,
  `recommended`, `permitted`, `informational`. Detected from regex matches
  on modal verbs (`must not`, `shall not`, `must`, `shall`, `should`,
  `may`, …). Stronger language wins. `requirement_phrases` lists the
  actual matched substrings so a human can sanity-check the label.
  (Known weakness: the regex can't distinguish "applies-to-this-section"
  modals from incidental ones — see "Upgrade path" below.)
* **`pages`** — list of page numbers covered by this snippet, derived from
  the `<!-- page N -->` markers emitted by the original pymupdf extraction.
* **`source_pdf`** — relative path to the PDF in this repo. The Context7
  rendering also produces a `#page=N` deep-link form
  (`nsf-resources/pappg-24-1.pdf#page=49`).
* **`source_url`** — canonical URL of record (PAPPG, OSTP, Federal
  Register, GWSW workbook landing). Empty when no public URL exists.
* **`source_label`** — pre-formatted citation, ready for the LLM to copy
  verbatim into review output. Format: `[<doc-label> §<section_path>, p.<page>]`.
* **`version`** — human-readable version / revision identifier of the
  source document (e.g. `"NSF 24-1"`). Helps reviewers flag stale rules.
* **`effective_date`** — ISO date the source took effect, when known.
* **`chunk_hash`** — `sha256:<16hex>` of the snippet text. Use as a cache
  key and to detect when a regeneration changed a chunk.
* **`cross_references`** — list of `{"raw": "...", "id": "..."}` parsed
  from "see Chapter X.Y" / "Section §X.Y" mentions. `id` is empty when
  the reference can't be resolved against the current snippet set
  (typically GWSW chapter-internal references that don't map to PAPPG).
* **`part` / `part_count`** — when a section was longer than
  `MAX_CHUNK_TOKENS` (1,200) it was split on paragraph boundaries; these
  fields identify the chunk position.

## How an LLM should use this

The recommended retrieval pattern is to call the BM25 retriever rather
than loading the whole snippet store:

```python
# From inside `nsf-resources-text/scripts/`
from retrieve import RetrievalIndex
idx = RetrievalIndex.load_default()
hits = idx.search("project summary page limit", top_k=5)
for h in hits:
    print(h.score, h.snippet["source_label"], h.snippet["title"])
```

Or from the command line:

```bash
python nsf-resources-text/scripts/retrieve.py "project summary page limit"
python nsf-resources-text/scripts/retrieve.py --doc pappg-24-1 --strength required \
    "single copy documents"
```

Cite results using the snippet's `source_label` field verbatim, e.g.
`[NSF PAPPG 24-1 §II.D.2.b, p.49]`. Quote at least one phrase from
`requirement_phrases` as evidence for the strength label.

For exhaustive checklist-style review, fall back to the per-doc JSONL
shard (`by-doc/pappg-24-1.jsonl`) so the LLM doesn't have to hold the
full 207k-token corpus in context.

## Retrieval evaluation

The retriever is evaluated against [`../eval/eval_set.jsonl`](../eval/eval_set.jsonl)
(**v2: 55 hand-labelled `query → expected_id` pairs across 33 tags**, grown
from the v1 seed of 15) plus a separate
[`../eval/adversarial.jsonl`](../eval/adversarial.jsonl) refusal set
(14 out-of-scope / fabricated-section / paraphrase-trap queries).

```bash
# Baseline BM25 over the 55-item set
python nsf-resources-text/scripts/run_eval.py

# Also score the adversarial / refusal set
python nsf-resources-text/scripts/run_eval.py --adversarial

# Try the Anthropic-style contextual chunks and parent-child expansion
python nsf-resources-text/scripts/run_eval.py --contextual --expand-parent

# Verbose per-item ranks (useful for diagnosing misses)
python nsf-resources-text/scripts/run_eval.py --adversarial -v
```

Reported metrics (BM25 baseline, no model deps):

| Set                                | Recall@5 | MRR   | Hit@1 |
| ---------------------------------- | -------- | ----- | ----- |
| v1 seed (15 items, pre-PR #11 v3)  | 0.867    | 0.733 | 0.600 |
| **v2 expanded (55 items)**         | **0.951** | **0.807** | **0.689** |
| v2 with `--contextual` (structural prefix) | 0.951 | 0.784 | 0.656 |

Adversarial / refusal set, BM25 baseline: **refusal rate ≈ 0.14** — i.e.
~86 % of the time naive BM25 confidently returns a plausible-but-wrong
PAPPG section for a question NSF's corpus doesn't actually answer. This
is the failure mode the dense reranker (§5.1 below) and the playbook's
`INSUFFICIENT EVIDENCE` rule are designed to fix.

Structural contextualization (Anthropic-style prefixes generated
without an LLM) is roughly neutral on this corpus; the published
+nDCG@5 gains come from genuine LLM-generated context — run
`contextualize.py --mode llm` once the Edison credit budget allows.

## Upgrade path

Per the synthesis in [`../../edison-trajectories/llm-doc-tokenization/result.md`](../../edison-trajectories/llm-doc-tokenization/result.md)
(§8 "Recommended Pipeline"), the v2 follow-up in
[`../../edison-trajectories/llm-doc-tokenization-feedback/result.md`](../../edison-trajectories/llm-doc-tokenization-feedback/result.md)
(§6 "Highest ROI"), and the framework-evaluation pass in
[`../../edison-trajectories/eager-framework-eval/result-literature.md`](../../edison-trajectories/eager-framework-eval/result-literature.md):

> **What's already in the tree (PR #11 round 4).**
> - `scripts/retrieve.py` — pure-stdlib BM25 (default).
> - `scripts/contextualize.py` — Anthropic-style chunk-prefix builder
>   (structural mode = no LLM call; `--mode llm` opt-in via Edison).
>   Writes `snippets.contextual.jsonl` + `parent_children.json`.
> - `scripts/retrieve.py --expand-parent` — parent-child expansion
>   that collapses sibling `~pN` chunks into one merged hit.
> - `scripts/retrieve_hybrid.py` — `--engine bm25 / hybrid / rerank`
>   scaffold that lazily loads `sentence-transformers` + BGE-M3 +
>   `bge-reranker-v2-m3` when invoked, falling back to stdlib BM25
>   otherwise. CI doesn't pay the model-download cost.
> - `eval/eval_set.jsonl` grown from 15 → 55 stratified queries +
>   `eval/adversarial.jsonl` (14-item refusal set) + `run_eval.py
>   --adversarial` for the refusal-rate proxy.

Remaining upgrade items (still optional, gated on model deps or
external API budget):

1. **Run the hybrid stack at scale.** Install
   `pip install sentence-transformers FlagEmbedding torch`, run
   `python scripts/retrieve_hybrid.py --build-index` once to cache
   BGE-M3 embeddings, then re-score:
   `python scripts/run_eval.py` against an updated harness that calls
   `HybridRetrievalIndex`. Published gain on regulatory corpora:
   +0.07 Recall@10, +0.08 MAP@10, +30–45 % nDCG@10 from the reranker.
2. **LLM-mode contextual prefixes.** `python scripts/contextualize.py
   --mode llm` (Edison ANALYSIS crow, ~1 credit per 500 chunks).
   Published end-to-end gain: 62-64 % → 72 % answer correctness.
3. **MCP stdio server** wrapping `RetrievalIndex` + `get_rule(id)` +
   `resolve_xref(raw)` tools so Claude Desktop / Cursor can call the
   retriever as a tool. Agent sessions in this repo can already shell
   out to `retrieve.py` directly.
   URL-prohibition rule that only applies to the Project Description).
4. **Swap pymupdf → Docling** (DocLayNet + TableFormer) for the
   extraction step. Better table recovery on `II.D.2.f` (Budget
   Justification) and on the GSS implementation plan's compliance
   matrices.
5. ~~Grow the eval set to 50-100 items~~ — **done in PR #11 round 4**
   (55 stratified items across 33 tags, plus 14 adversarial items).
   Future work: claim-level faithfulness scoring via
   [RAGChecker](https://github.com/amazon-science/RAGChecker) or
   [ARES](https://github.com/stanford-futuredata/ARES) (needs an LLM
   in the loop).

## Regenerating

```bash
python nsf-resources-text/scripts/tokenize_corpus.py
python nsf-resources-text/scripts/contextualize.py   # (optional) Anthropic-style prefixes
```

The script is deterministic: rerun whenever the source markdown in
`nsf-resources-text/` changes. Outputs in this directory are
auto-generated — do not edit by hand.
