# Ax (meta/Ax) digest: FAILED vs ABANDONED (and EARLY_STOPPED, STALE) for multi-stage experiments

Scope and provenance
- Code: `meta/Ax` `main` at **`5beadc82256d419f75768a89f1a4c357bc4a63c0`** (2026-11-25, "Support outcome constraints in preference optimization (#5324)"). All code links below are pinned to that SHA. Latest release: 1.3.1 (2026-06-09). Reference commit `41cdcef` (2026-11-17) is on main; only #5323 and #5324 landed after it.
- Threads: all 896 issues and 4,389 PRs with bodies, comments and PR reviews (GraphQL, 2026-11-26) (downloaded with `scripts/ax_fetch.py`; not committed). Most Ax PRs are exported from Meta's internal Phabricator and show `merged=false` on GitHub; whether a PR landed was decided from `main`'s commit messages .
- Behavior marked **[verified]** was reproduced by running the preinstalled Ax 1.3.1 (identical to `main` in the functions involved; diffs are type-checker comments only) with `verify/ax_verify_semantics.py` and `verify/ax_verify_running_partial.py`; the outputs are in `verify/*.out`.

Shorthand: `B` = `https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0`

## Key takeaways

1. **Since 1.2.2, FAILED trials contribute no data.** Default fitting uses only `RUNNING`, `COMPLETED` and `EARLY_STOPPED` ([B/ax/core/data_utils.py#L83-L101](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/data_utils.py#L83-L101), [#4614](https://github.com/meta/Ax/pull/4614)). A FAILED stage-k run therefore throws away valid data from stages before k **[verified]**. The docstring still says "all statuses except ABANDONED".
2. **ABANDONED = excluded from fitting + kept as a pending point; FAILED = excluded + re-suggestable.** FAILED arms are removed from the dedup set ([#2488](https://github.com/meta/Ax/pull/2488)). Maintainer phrasing: FAILED is "as if it had never happened"; ABANDONED has "a repelling effect" ([#4642](https://github.com/meta/Ax/issues/4642#issuecomment-3648488851)).
3. **Partial data is first-class only through `Client.complete_trial` (≥1.2.4).** The trial stays `COMPLETED` and the partial data are fitted per metric ([#4958](https://github.com/meta/Ax/pull/4958)). The deprecated `AxClient.complete_trial` still marks such trials FAILED **[verified]**.
4. **Pending-point protection for partially observed arms is weaker than documented.** `X_pending` is the *intersection* of the per-metric pending sets over objective and constraint metrics. In experiments with fewer than 100 trials, a COMPLETED-partial trial, a RUNNING trial with stage-1 data, or an ABANDONED trial with some data is **not** in `X_pending` **[verified]**. Only exact-duplicate rejection (`should_deduplicate=True`) protects it.
5. **`AddExecutionViability` (PR #4547, 1.3.0) is opt-in, trial-level and binary (ABANDONED→0), and broken as shipped.** In 1.3.x/main, `TorchAdapter` raises `KeyError: Metric 'execution_viable' not found` unless you register a metric with that name **[verified]**. The classifier models and failure-aware benchmark runner that complete the stack ([#4555](https://github.com/meta/Ax/pull/4555), [#5072](https://github.com/meta/Ax/pull/5072), [#4948](https://github.com/meta/Ax/pull/4948)) are unmerged.
6. **Orchestrator metric-fetch errors changed meaning three times.** They marked trials FAILED (≤1.2.2), then ABANDONED (1.2.3–1.3.1, [#4779](https://github.com/meta/Ax/pull/4779)), and on unreleased `main` leave the status unchanged but count toward the failure rate ([#5287](https://github.com/meta/Ax/pull/5287)).
7. **No per-stage, per-metric or function-network notion exists.** Status lives on trials (plus arm-level abandonment in `BatchTrial`). "Metric availability" is computed from data presence only. Nothing in code, branches or threads models BOFN/EIFN/pKGFN-style networks.

## (a) Code-level semantics on `main`

### Summary table (defaults; Client-generated GS; single-arm `Trial`s)

| Status | Fitted? | Pending / in `X_pending`? | Exact re-suggestion (dedup on) | Failure rate | `AddExecutionViability` label |
|---|---|---|---|---|---|
| CANDIDATE | no | pending for all metrics | blocked | no | – |
| STAGED | no (even if data attached) | pending for metrics without data | blocked | no | – |
| RUNNING | yes (attached data) | pending for metrics without data; in `X_pending` only if missing *every* objective/constraint metric (<100 trials) | blocked | no | 1 if it has data |
| COMPLETED | yes | partial-data arms pending for missing metrics (≥1.2.4); same intersection caveat | blocked | only if opt-config data incomplete (main, unreleased) | 1 |
| EARLY_STOPPED | yes | never pending ([#4450](https://github.com/meta/Ax/pull/4450) open) | blocked | no | 1 |
| FAILED | **no** (≥1.2.2) | never | **allowed** | yes | not present (filtered) |
| ABANDONED | no (unless `fit_abandoned`) | pending for metrics without data | blocked | yes | **0** |
| STALE | no | never | **blocked** (contrary to docstring) | no | – |
| abandoned arm (BatchTrial) | no | not pending since [#4955](https://github.com/meta/Ax/pull/4955) | blocked | – | – |

### Fitting (which statuses' data reach the model)
- The lifecycle docstring calls FAILED "retryable" and ABANDONED "non-retryable", and says STALE "can be re-suggested" ([B/ax/core/trial_status.py#L17-L64](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/trial_status.py#L17-L64)). Its NOTE that MapMetric data are excluded unless the trial completes is out of date: `fit_only_completed_map_metrics` has defaulted to `False` since [#3978](https://github.com/meta/Ax/pull/3978) (1.1.0). The status-set constants are at [B/ax/core/trial_status.py#L150-L182](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/trial_status.py#L150-L182).
- `DataLoaderConfig.statuses_to_fit` returns `STATUSES_EXPECTING_DATA` = {RUNNING, COMPLETED, EARLY_STOPPED}. With `fit_abandoned=True` it returns **every** status, so FAILED, CANDIDATE and STALE data come back too. `statuses_to_fit_map_metric` is `{COMPLETED}` only when `fit_only_completed_map_metrics=True` ([B/ax/core/data_utils.py#L83-L101](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/data_utils.py#L83-L101)).
- Rows are filtered per metric by trial status. Rows for arms abandoned inside batch trials are relabeled ABANDONED first ([B/ax/core/data_utils.py#L453-L481](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/data_utils.py#L453-L481)).
- Each outcome gets its own dataset with NaN rows dropped. Per-metric missingness is therefore native: a stage-1 metric trains on every trial that measured it ([B/ax/adapter/torch.py#L449-L475](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/torch.py#L449-L475)). In the toy run, `s1` trained on trials {0–5, 6 (COMPLETED partial), 13 (EARLY_STOPPED)} and `y` on {0–5}. The FAILED trial's and the ABANDONED trial's `s1` values were dropped **[verified]**.
- `DataLoaderConfig` is an adapter kwarg, so it is set through `GeneratorSpec(generator_kwargs={"data_loader_config": ...})`. The Client exposes no knob for it.

### Candidate generation: pending points and dedup
- `extract_pending_observations` dispatches by size. Below 100 trials (or with BatchTrials) it uses the exact per-metric function; at 100 or more single-arm trials it uses a fast status-based one ([B/ax/core/utils.py#L276-L313](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/utils.py#L276-L313)).
- In the exact path, an arm is pending for metric *m* if its trial is CANDIDATE, or if it is STAGED/RUNNING/COMPLETED/ABANDONED and has no data for *m* ([B/ax/core/utils.py#L384-L400](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/utils.py#L384-L400)). FAILED, EARLY_STOPPED and STALE trials are never pending.
- The fast path marks all arms of CANDIDATE/STAGED/RUNNING/ABANDONED trials pending for every metric. It adds COMPLETED trials whose `MetricAvailability` is INCOMPLETE or NOT_OBSERVED ([B/ax/core/utils.py#L405-L495](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/utils.py#L405-L495)). Availability is purely "does the opt-config metric appear in the trial's data" ([B/ax/core/utils.py#L160-L270](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/utils.py#L160-L270)).
- **Intersection.** Per-metric pending lists become per-outcome arrays ([B/ax/adapter/adapter_utils.py#L521-L553](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/adapter_utils.py#L521-L553)). `X_pending` then keeps only points that are pending for *all* objective and constraint outcomes ([B/ax/generators/torch/utils.py#L196-L206](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/generators/torch/utils.py#L196-L206), [B/ax/generators/utils.py#L548-L583](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/generators/utils.py#L548-L583)). Out-of-bounds pending points are also dropped ([#1568](https://github.com/meta/Ax/issues/1568)).
- **[verified] consequences.** The exact path's `X_pending` held only {ABANDONED-no-data ×3, RUNNING-no-data}. COMPLETED-partial (6) and ABANDONED-with-`s1` (8) were absent. The fast path held {6, 8, 9, 10, 11, 12}. A RUNNING trial with only stage-1 data attached got `X_pending = None`.
- **Dedup.** `arms_by_signature_for_deduplication` holds every arm except those in FAILED trials ([B/ax/core/experiment.py#L527-L544](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/experiment.py#L527-L544)). Generation is retried up to `MAX_GEN_ATTEMPTS` before raising `GenerationStrategyRepeatedPoints` ([B/ax/generation_strategy/generation_node.py#L602-L638](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/generation_strategy/generation_node.py#L602-L638)). The Client's default Sobol and MBM nodes use `should_deduplicate=True`. Sobol's budget criterion ignores FAILED/ABANDONED trials ([#4776](https://github.com/meta/Ax/pull/4776)), and the BO transition needs COMPLETED trials with data ([B/ax/api/utils/generation_strategy_dispatch.py#L70-L108](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/utils/generation_strategy_dispatch.py#L70-L108), [#L184-L194](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/utils/generation_strategy_dispatch.py#L184-L194)). STALE arms stay in the dedup set, so "retryable" STALE arms cannot be re-proposed exactly.
- **Infeasibility fallback.** If no observed point satisfies all outcome constraints (and MOO thresholds), acquisition switches to `qLogProbabilityOfFeasibility` ([B/ax/generators/torch/botorch_modular/utils.py#L444-L499](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/generators/torch/botorch_modular/utils.py#L444-L499); [#3585](https://github.com/meta/Ax/pull/3585), [#4890](https://github.com/meta/Ax/pull/4890)). This acts on modeled constraint metrics, not on trial statuses.

### Client API semantics with missing metrics
- **`Client.complete_trial` (main/≥1.2.4)** always marks COMPLETED. It logs a warning ("Partial data will still be used for modeling") when opt-config metrics are missing ([B/ax/api/client.py#L531-L573](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/client.py#L531-L573)).
  - Before [#4958](https://github.com/meta/Ax/pull/4958) (0.5.0–1.2.3, from [#3121](https://github.com/meta/Ax/pull/3121)), the same call marked the trial **FAILED** with reason "`{missing} are missing`". Combined with #4614, users of 1.2.2–1.2.3 silently lost partial data, and the arm became re-suggestable.
  - #4958's own summary: marking FAILED "discarded useful partial data from model fitting, allowed re-suggestion of already-evaluated arms, and excluded trials from analysis". It landed before the 1.2.4 tag, but the 1.2.4 CHANGELOG omits it. So does the 1.2.2 CHANGELOG for #4614.
- **`Client.attach_data`** attaches without completing. Since [#5135](https://github.com/meta/Ax/pull/5135) (1.3.0), unknown metric names are auto-registered as tracking metrics ([B/ax/api/client.py#L575-L606](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/client.py#L575-L606)).
- **`mark_trial_failed(trial_index, failed_reason)`, `mark_trial_abandoned(trial_index)`, `mark_trial_early_stopped(trial_index)`** are at [B/ax/api/client.py#L690-L741](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/client.py#L690-L741). Only FAILED takes a reason through the Client.
- **Core `mark_*` methods** ([B/ax/core/base_trial.py#L640-L747](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/base_trial.py#L640-L747)):
  - FAILED is allowed only from RUNNING, and ABANDONED from any non-terminal state.
  - EARLY_STOPPED requires RUNNING *and* existing data ("Please mark trial abandoned instead", [#3446](https://github.com/meta/Ax/pull/3446)).
  - STALE is allowed only from CANDIDATE.
  - `unsafe=True` bypasses all of these. One `status_reason` field replaced `failed_reason`/`abandoned_reason` in [#4763](https://github.com/meta/Ax/pull/4763) ([L542-L545](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/base_trial.py#L542-L545)).
  - A COMPLETED trial cannot be re-labeled through the Client: `ValueError: Cannot abandon a trial in a terminal state` / `TrialMutationError` **[verified]**. The workaround is private `client._experiment.trials[i].mark_abandoned(unsafe=True)` ([#4470](https://github.com/meta/Ax/issues/4470#issuecomment-3469903843)).
- **Legacy `AxClient`** is deprecated, with removal planned for 1.4.0 ([B/ax/service/ax_client.py#L187-L194](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/ax_client.py#L187-L194)).
  - `complete_trial` still calls `mark_failed()` when any opt-config metric is missing ([B/ax/service/ax_client.py#L1640-L1650](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/ax_client.py#L1640-L1650), [#2082](https://github.com/meta/Ax/pull/2082), 0.3.7) **[verified]**.
  - `log_trial_failure` takes no reason ([L976-L992](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/ax_client.py#L976-L992)); `abandon_trial(reason)` does ([L874-L881](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/ax_client.py#L874-L881)).

### `AddExecutionViability` ([PR #4547](https://github.com/meta/Ax/pull/4547), landed 2026-03-12, release 1.3.0)
- **What it is.** An adapter transform, written by Meta's sunnyshen321, reviewed by saitcakmak, and originally titled `AddFeasibility`. The PR body suggested a different word to avoid confusion with outcome-constraint feasibility. It is not in any default transform list; it appears only in the storage registry ([B/ax/storage/transform_registry.py#L108](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/storage/transform_registry.py#L108)). It is **opt-in**: add it to `transforms` and configure it under `transform_configs["AddExecutionViability"]`. It has had no changes since landing.
- **Activation.** Config `min_abandoned_trials` (default 3) and `feasibility_threshold` (default 0.8). It counts `experiment.trials_by_status[ABANDONED]`; below the threshold it is a no-op ([L35-L92](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/transforms/add_execution_viability.py#L35-L92)).
- **Labels.** It adds column `execution_viable` with mean 0.0 for rows of ABANDONED trials and 1.0 for every other row in the (already status-filtered) training data, with SEM NaN (noise inferred). ABANDONED trials missing from the data get synthetic rows (NaN for the real metrics) ([L133-L182](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/transforms/add_execution_viability.py#L133-L182)). Consequences:
  - FAILED trials are never labeled.
  - RUNNING and EARLY_STOPPED trials with data count as viable.
  - Abandoned arms inside a `BatchTrial` are not counted.
- **Constraint.** It appends `OutcomeConstraint(execution_viable >= threshold, relative=False)` and adds the outcome to the adapter ([L222-L244](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/transforms/add_execution_viability.py#L222-L244)). The docstring says "P(execution_viable) >= threshold". In practice a GP is fit to the 0/1 labels like any metric, and the default constrained acquisition weights by the modeled probability that this regression output exceeds the bound. It is not a classifier.
- **[verified] breakage.** Since [#5000](https://github.com/meta/Ax/pull/5000) (1.3.0, four days after #4547), `TorchAdapter` resolves every opt-config metric by name ([B/ax/adapter/torch.py#L1080-L1083](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/torch.py#L1080-L1083) → [B/ax/core/experiment.py#L823-L839](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/experiment.py#L823-L839)). `gen` raises `KeyError` for `execution_viable`.
  - Workaround: register a tracking metric named `execution_viable` (`client.configure_tracking_metrics(["execution_viable"])`). With it, the viability dataset had 12 rows (8×1.0, 4×0.0) and the constraint row appeared in `A`/`b`. Placing the transform before `Y_trans` standardizes the labels and bound consistently.
  - The unit tests only exercise the transform methods, so the breakage is untested.
- **Neighbouring work by the same author.** The benchmark NaN→ABANDONED runner ([#4964](https://github.com/meta/Ax/pull/4964), 1.2.4), the oracle trace counting ABANDONED ([#4953](https://github.com/meta/Ax/pull/4953)), and a custom tolerated failure rate for "failure aware benchmark problems" ([#4954](https://github.com/meta/Ax/pull/4954)) all landed. Still **open**: RF/SVC/XGBoost "models for modeling deterministic failures" ([#4555](https://github.com/meta/Ax/pull/4555)), `SoftKNNClassifierModel` ([#5072](https://github.com/meta/Ax/pull/5072), BoTorch [#3243](https://github.com/meta-pytorch/botorch/pull/3243) open), and `FailureAwareBenchmarkRunner` plumbing ([#4948](https://github.com/meta/Ax/pull/4948)).

### Orchestrator (formerly Scheduler) failure handling
- **Options.** `tolerated_trial_failure_rate=0.5`, `min_failed_trials_for_failure_rate_check=5`, `ttl_seconds_for_trials` ([B/ax/orchestration/orchestrator_options.py#L51-L69](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator_options.py#L51-L69), [#L128-L151](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator_options.py#L128-L151)). The TTL docstring ("RUNNING ... will be marked FAILED") is stale. TTL now only turns CANDIDATE into STALE ([B/ax/core/base_trial.py#L833-L843](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/base_trial.py#L833-L843); [#4221](https://github.com/meta/Ax/pull/4221), [#4542](https://github.com/meta/Ax/pull/4542)).
- **Failure rate.** "Bad" = FAILED + ABANDONED trials created by this Orchestrator, plus (main only) COMPLETED trials whose opt-config data are incomplete. It is divided by all trials created by this Orchestrator ([B/ax/orchestration/orchestrator.py#L1082-L1147](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator.py#L1082-L1147), [#L1428-L1462](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator.py#L1428-L1462)). Once exceeded, no new trials are scheduled, pending ones finish ([#3070](https://github.com/meta/Ax/pull/3070)), and `FailureRateExceededError` is raised. ABANDONED has counted since [#1255](https://github.com/meta/Ax/pull/1255) (0.2.10). `Client.run_trials` exposes only the rate ([B/ax/api/client.py#L743-L772](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/client.py#L743-L772)).
- **Status updates.** Runner-polled FAILED/ABANDONED statuses take their reason from `runner.poll_exception` ([B/ax/orchestration/orchestrator.py#L1499-L1506](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator.py#L1499-L1506)).
- **Retries.** Deployment and polling are retried 3× (`@retry_on_exception`). A FAILED trial is never re-run automatically; "retryable" only means the generator may propose that arm again.
- **Metric fetch errors on main.** The error is logged and cached per (trial, metric) in `Experiment._metric_fetching_errors` ([B/ax/core/experiment.py#L1893-L1926](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/experiment.py#L1893-L1926)). The status stays unchanged ([B/ax/orchestration/orchestrator.py#L2105-L2171](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator.py#L2105-L2171)). This came from [#5287](https://github.com/meta/Ax/pull/5287) (2026-09-21, unreleased), which superseded [#5119](https://github.com/meta/Ax/pull/5119). `Metric.recoverable_exceptions` was then removed ([#5120](https://github.com/meta/Ax/pull/5120)). Before that, `_mark_err_trial_status` marked trials FAILED, and from 1.2.3 ABANDONED ([#4779](https://github.com/meta/Ax/pull/4779): "so that it is less likely to be tried again").

### Early stopping
- **How it is applied.** The Orchestrator checks the strategy only when new data arrive. It calls `experiment.stop_trial_runs`, which calls `runner.stop` and then `mark_early_stopped(reason)` ([B/ax/orchestration/orchestrator.py#L1362-L1381](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/orchestration/orchestrator.py#L1362-L1381), [B/ax/core/experiment.py#L1615-L1645](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/experiment.py#L1615-L1645)). Client users call `should_stop_trial_early`, then `mark_trial_early_stopped` ([B/ax/api/client.py#L661-L687](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/api/client.py#L661-L687)).
- **How partial data are used.** Partial curves from EARLY_STOPPED trials are fitted. `latest_rows_per_group=1` keeps the last progression, and `MapKeyToFloat` turns progression into an input feature that is fixed to the target at generation ([B/ax/adapter/registry.py#L100-L107](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/adapter/registry.py#L100-L107); [#3978](https://github.com/meta/Ax/pull/3978), [#4462](https://github.com/meta/Ax/pull/4462)). For non-map metrics, the early-stopped value is fitted as if it were final.
- **Duplicates.** Because early-stopped arms are not pending, the surrogate can re-propose them. [#4450](https://github.com/meta/Ax/pull/4450) (open) would make them pending.
- **Arm-level stopping.** An `ArmStoppingStrategy` was proposed and abandoned ([#5134](https://github.com/meta/Ax/pull/5134), closed 2026-05-28).

### Trial vs arm vs metric level; multi-stage
- **Status lives on trials.** Arm-level abandonment exists only for `BatchTrial` ([B/ax/core/batch_trial.py#L481-L505](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/batch_trial.py#L481-L505)).
- **Metric level is not a status.** It is either the presence or absence of data (`MetricAvailability`) or a cached fetch error used by the `MetricFetchingErrors` healthcheck. The model never sees a reason.
- **Best point** uses only COMPLETED trials with COMPLETE availability. **Traces** use COMPLETED and EARLY_STOPPED with complete data ([B/ax/service/utils/best_point.py#L131-L155](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/utils/best_point.py#L131-L155), [#L1298-L1326](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/service/utils/best_point.py#L1298-L1326)).
- **Benchmark module.** NaN-valued trials become ABANDONED ([B/ax/benchmark/benchmark_runner.py#L301-L324](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/benchmark/benchmark_runner.py#L301-L324)). The oracle trace carries the best value forward over FAILED/ABANDONED trials ([B/ax/benchmark/benchmark.py#L233-L247](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/benchmark/benchmark.py#L233-L247), [#L516-L534](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/benchmark/benchmark.py#L516-L534)).
- **Multi-stage primitives.** The closest ones are:
  - `DerivedMetric`/`ExpressionDerivedMetric` (1.2.4): a deterministic function of other metrics, computed before modeling ([B/ax/core/derived_metric.py#L9-L39](https://github.com/meta/Ax/blob/5beadc82256d419f75768a89f1a4c357bc4a63c0/ax/core/derived_metric.py#L9-L39)).
  - Multi-type experiments and task parameters, i.e. multi-task GPs ([#2546](https://github.com/meta/Ax/issues/2546#issuecomment-2248978213)).
  - Neither models stage outputs as inputs to later stages.
- **Newer than `41cdcef`.** The only new commit touching constraints is [#5324](https://github.com/meta/Ax/pull/5324) (outcome constraints for preference optimization, with the p(feasible) fallback). Nothing newer touches failed or abandoned handling.

## (e) Gaps that matter for multi-stage experiments with stage-level failures

1. **No stage or node status.** A trial is one status. "Failed at stage k" must be encoded as which metrics exist plus an external reason. `status_reason` is free text, and the Client sets it only for FAILED.
2. **FAILED and ABANDONED both discard good upstream data.** `fit_abandoned=True` re-admits everything, including FAILED, CANDIDATE and STALE, so it is a blunt instrument. There is no "trust stages < k" option.
3. **Partial arms are weakly protected.**
   - Under 100 trials, partially observed arms (COMPLETED or RUNNING) and ABANDONED-with-data arms are missing from `X_pending`. At 100 or more trials they are included. Benchmark results can therefore change at that size boundary.
   - ABANDONED arms with some data are neither fitted nor pending, so the model is blind to them apart from exact dedup.
4. **The failure model is trial-level, binary and only fed by ABANDONED.**
   - No stage-specific viability, no per-node classifier, no FAILED-vs-deterministic inference.
   - Labels come from a GP on 0/1 values, activated after 3 abandonments.
   - It needs a registered-metric workaround to run on 1.3.x/main.
   - True classifiers are unmerged.
5. **Version sensitivity.**
   - The meaning of ABANDONED changed with Orchestrator fetch handling (1.2.3–1.3.1 vs main).
   - `complete_trial` with missing metrics → FAILED (0.5.0–1.2.3) vs COMPLETED (≥1.2.4).
   - FAILED fitted (≤1.2.1) vs not fitted (≥1.2.2).
   - The legacy `AxClient` is still FAILED-on-missing.
   - Pin the version in any benchmark.
6. **No re-labeling, retry lineage or planned/executed split.**
   - A completed stage-1 trial cannot be abandoned later via the public API.
   - A re-run of stage k on the same upstream material has no first-class representation; a new trial with the same arm duplicates the arm, and replicated upstream data would be double-counted.
   - Planned vs executed parameters are a wishlist item (#3577).
7. **No function-network modeling and no partial-evaluation acquisition.** Stage outputs cannot feed later stages as model inputs. Costs per stage are not modeled. `DerivedMetric` composes values but not uncertainty structure.
8. **Docs are stale on precisely these points.** The `statuses_to_fit` docstring, the `TrialStatus` NOTE, the Orchestrator TTL docstring, the "STALE re-suggestable" claim (blocked by dedup), and the CHANGELOG omissions of #4614/#4958.

## (f) Recommendations: recording a run that fails at stage k (powder → print → test)

**What Ax supports today**, with the Client on a pinned version ≥1.2.4 (ideally 1.3.1 or main):
1. **One metric per measured stage output.** For example `powder_yield`, `d50` (stage 1), `relative_density`, `printable` (stage 2), `uts` (stage 3). The objective is the final property. Add outcome constraints only where a stage threshold is physically meaningful, such as `relative_density >= 0.98`.
2. **Attach as you go.** Call `client.attach_data(i, {...})` when each stage finishes. RUNNING data are fitted immediately. Do not call `complete_trial` until the run's fate is known; a COMPLETED trial cannot be re-labeled.
3. **Parameter-caused failure at stage k** (e.g. powder will not spread or prints crack):
   - Preferred: `complete_trial(i, {stage<k metrics..., f"stage{k}_viable": 0.0})` and record the reason in your ledger. The upstream metrics keep training their GPs. The viability metric, used as an outcome constraint (`>= 0.5`), lets constrained acquisition learn the failure region. This is maintainer-endorsed ([#1392](https://github.com/meta/Ax/issues/1392#issuecomment-1403841061), [#2460](https://github.com/meta/Ax/issues/2460#issuecomment-2115746662)). #2548 called it unsupported in 2024, but `Client` made partial completion intentional in 1.2.4. Ax falls back to p(feasible) if nothing is feasible yet. Report 1.0 for runs that pass stage k and omit the metric for runs that never reached it. Prefer a continuous margin (e.g. density) over 0/1 where it exists. Never invent extreme objective values.
   - Alternative: `mark_trial_abandoned(i)`, optionally with `AddExecutionViability` plus `configure_tracking_metrics(["execution_viable"])`. Accept that upstream data are dropped from fitting (or set `DataLoaderConfig(fit_abandoned=True)`, which also re-admits FAILED data).
4. **Transient or operational failure at stage k** (printer jam, lost specimen):
   - If you will re-run stage k on the same material soon, leave the trial RUNNING and attach later ([#2460](https://github.com/meta/Ax/issues/2460#issuecomment-2115791953)). Upstream data are used. Note that the arm is not in `X_pending` while partial.
   - Otherwise, `mark_trial_failed(i, failed_reason="stage2: printer jam")`. Upstream data stop being fitted but remain stored; the arm may be re-suggested and counts toward the failure rate.
   - For a later retry, `attach_trial` the same parameters and `complete_trial` it with all stage metrics (copying the reused lot's upstream values). Each measurement is then fitted once, because the FAILED trial is excluded, and the retry has COMPLETE availability for best point and trace **[verified]**. The arm is reused, and because it sits in a FAILED trial it leaves the dedup set. Splitting stages across two COMPLETED trials makes neither COMPLETE.
5. **Executed parameters differ from planned ones** (#3577 pattern): abandon the planned trial and `attach_trial` the executed parameters. Record the link in the ledger.
6. **Stage metadata.** Put lot IDs, stage, reason and timestamps in `trial.update_run_metadata({...})` / `_properties` ([#1773](https://github.com/meta/Ax/issues/1773#issuecomment-1673419999)), which models ignore. Also keep them in your own store.
7. **Settings.** Keep `should_deduplicate=True`. For benchmarks below 100 trials, be aware of the `X_pending` intersection (or call the fast pending function yourself). Set `tolerated_trial_failure_rate` deliberately (default 0.5, checked after 5 bad trials).

**What needs a custom ledger or extension:**
- A per-stage status table keyed by trial index, arm, stage and material lot. It should hold status (ok, failed-deterministic, failed-transient, skipped), reason, cost, timestamps and retries.
- From that ledger, build node-level datasets: every run that reached node j trains node j. Feed them to a BoTorch function-network or classifier model through a custom `Surrogate` or `ExternalGenerationNode`, because Ax cannot represent stage outputs as inputs.
- Benchmark arms worth comparing:
  - FAILED (drop all)
  - ABANDONED (drop + pending)
  - COMPLETED-partial + stage-viability constraint
  - ABANDONED + `AddExecutionViability` (with the workaround)
  - ledger-driven node-level models
- Ax's own oracle trace convention (carry forward the best value over FAILED/ABANDONED trials, #4953) is a reasonable regret definition to reuse.
